# The Foundry: a practice-time asset factory for livecode

## Thesis

The factory is **4 parallel fabrication cells**, each a fully independent server+headless-browser stack, driven by fabricator subagents, feeding a **gate-checked, generated catalog** that the stage agent greps in one Read. Gene runs `python factory/run.py --cells 4 --session figurative` and walks away; he curates asynchronously via a contact-sheet HTML that regenerates every 30 minutes. Nothing enters the catalog without passing machine gates; nothing reaches "gold" rank without Gene's thumb.

The key unlock nobody should miss: **the factory host is Playwright, so verification gets `page.evaluate()`** — direct reads of `window.state`, canvas pixels, fps, and audio meter values. The live autopilot is stuck with snapshots and `/errors`; the factory is not. Verification can be far more rigorous offline than anything possible on stage, which is exactly the point of moving work to practice time.

## Asset format (the unit the factory produces)

Extend the proven `autopilot/{creatures,worlds,...}` pattern (`{"name","code"}` JSON, POST to `/p5/layer`) into a three-part asset directory, in-repo and durable (the `/tmp/scene_queue` library died on reboot — never again):

```
assets/
  visual/character/penguin_dj/
    asset.json          # metadata + param schema + gate results (machine-written)
    template.js         # p5 draw-body, string.Template ${placeholders} (NOT f-strings — brace-doubling is untenable at scale)
    preview/            # strip.jpg (3-frame filmstrip), sweep_0..2.jpg, motion.gif — committable
  music/house/bass_rolling/
    asset.json
    template.strudel    # ends in .play(), ${root} ${gain} ${lpf} placeholders, NO .cps()
    preview/            # bounce.webm (local-only, gitignored), meter.json (RMS/band analysis, committed)
  CONTRACT.md           # the authoring contract (below)
catalog/
  catalog.jsonl         # one line per PASSED asset — generated, never hand-edited
  INDEX.md              # greppable one-line-per-asset digest — generated from catalog.jsonl
  pending/<cell>.jsonl  # per-cell append files, folded in by the orchestrator (no write contention)
  graveyard/            # killed assets + reason (dedup negative examples)
```

`CONTRACT.md` codifies what today is implicit and load-bearing: wall-clock beat sync (`cps = window.state.cps || 0.5; beat from millis()`, the cat.json convention — hardcoded 28.8 is a lint failure); state namespace = `window.state[layerName] = {}` only; canonical layer slots with z-order (`__bg`=0, `floor`=10, `mid`=30, `subject`=50, `props`=60, `fx`=80, `post`=99 — asset.json declares its slot, installers post in slot order); music slot→orbit map (perc/fx=2, bass=3, chords=4, lead=5, pad=6, sparkle=7, vox=8); per-role gain budgets; whiteout rules (ADD alpha ≤35 on large shapes, beams ≤height*0.4, opaque `__bg` first); resolution-agnostic sizing (`min(width,height)` scaling, cache buffers keyed on w/h); sample deps declared in `asset.json.deps`, never loaded inside asset code.

## The fabrication cell: per-asset pipeline

Each cell owns one `LivecodeController(ws_port=P-1, http_port=P)` (ports 9000/8999, 9010/9009, …) plus one headless Playwright Chromium pointed at `localhost:P/livecode.html` — `factory/stack.py`, a ~150-line fork of `autopilot_host.py` (which already handles auto-clicking Start, reload recovery, canvas capture). At boot each stack: POSTs `/show/recording {enabled:false}` (keeps smoke tests out of `shows/unsorted` autosaves), preloads the sample-pack manifest, and injects the **meter snippet** once via `/strudel/send`: an AnalyserNode on the shared `getAudioContext()` writing `window.state.__meter = {rms, peak, bass, mid, treble, t}` every 250ms, plus an fps tracker. Playwright reads it all via `page.evaluate()`.

Pipeline stages, hard-gated in order:

1. **IDEATE** — pop a work order from `factory/queue.jsonl`. Work orders are pre-generated by the orchestrator from: `autopilot/ideas.md` (~350 bullets, ready-made), the genre-whitespace list (trance/electro/italo/footwork/gamelan/… have zero coverage), and Gene's typed requests. A work order carries category, subject, **mandatory style constraint** (palette discipline, technique — this is where diversity is enforced, not hoped for), and required param axes.
2. **AUTHOR** — fabricator writes `template.js`/`.strudel` + `asset.json` param schema against CONTRACT.md. Harvest-mode work orders instead extract from the existing corpus (disco_dancers rig, full_show.show.json's 92 track + 42 layer literals, journal-proven code).
3. **STATIC LINT** (no server, <1s) — `node --check` on the compiled-with-defaults code wrapped in a function; banned-API scan (`createCanvas`, `setup(`, `setcps`, `gm_`, `.swingBy`, `async`, `import`, embedded `.cps(`, hardcoded `28.8`/`frameCount/2` beat math); every schema param appears in template, no stray `${`; `.bank("X")`/`s("pack:")` references cross-checked against declared `deps`; whiteout heuristics (ADD + alpha>35 + large radius).
4. **DEPLOY** — compile defaults via `string.Template`, POST to the cell's own server. Visuals deploy **over the standard test bed** (a canonical `__bg` world + floor) so they're judged in context; music deploys **into the standard verification mix** (a neutral drums+bass playing) so level balance is real.
5. **VERIFY-VISUAL** — over 10s: (a) `/errors` empty for this layer; (b) fps ≥ 30 via page.evaluate (margin over the ≥20 stage floor, because stage runs retina fullscreen); (c) motion gate: mean pixel diff between frames at t=1/4/8s must be above a static floor AND below a strobe ceiling; (d) luminance histogram: no blackout, no whiteout; (e) **LLM self-judge** on the 3-frame strip: "recognizably a {subject}? composition 1–5, one-line critique" — a–d are auto-fail, (e) is recorded and gates only below 2/5.
6. **VERIFY-MUSIC** — (a) 2s after POST, track present in `/status` and `/errors` empty (the silent-parse-failure trap); (b) meter: RMS above silence floor **within 2s** (the never-silent mandate, verified per-asset so the stage agent can skip its 2s recheck), peak below clipping ceiling, onset density in the declared role's range (drums busy, pad sparse); (c) 8s MediaRecorder bounce from a MediaStreamDestination → local `.webm` for the contact sheet.
7. **PARAM SWEEP** — 3 seeded random vectors within declared ranges; redeploy each; re-run cheap gates (errors/fps/silence/whiteout). Plus the **param-responsiveness gate**: default vs. sweep-vector output must differ (pixel diff / meter diff above threshold) — an asset that ignores its params fails. All 3 vectors must pass or ranges get narrowed and the sweep reruns once; second failure kills the asset.
8. **TEMPO SWEEP** (visual + music-visual pairs) — rerun at cps 0.36 and 0.85 via `/p5/state`; motion gate must still pass, catching any residual frame-count sync.
9. **CATALOG** — on full pass, append the entry (metadata + gate numbers + preview paths + defaults + 3 known-good sweep vectors) to `catalog/pending/<cell>.jsonl`. Fail → `graveyard/` with the failing gate and judge critique attached; "fixable" failures re-queue once with the critique as a note.

Cost per asset ≈ 5–7 min (author 2–4, verify ~1.5, sweeps ~1.5) → **8–10 assets/hour/cell, ~35/hour for the ranch, ~100 verified assets per 3-hour session.**

## Batch architecture

- **4 cells** is the target (one M-series laptop: 4 headless Chromium + p5 canvases is CPU-real; more cells makes the fps gate noisy from contention). Start at 2, watch host load.
- **Full isolation, no time-slicing**: `--port` already parameterizes the server; each cell's browser, timeline, `/errors` deque, and window.state are private. The only shared resources are the queue and catalog — both append-only files with per-cell staging, folded by the orchestrator. Nothing ever touches port 8766 (the live/default port); `factory/stack.py` refuses to start on it.
- **Because fps is contention-sensitive**, the fps gate runs in a brief **quiet slot**: cells take a file-lock token for the 10s measurement window so at most 2 measure concurrently. Everything else runs fully parallel.
- **Orchestrator** (the main Claude session Gene launches): generates the work-order queue, spawns/monitors fabricator subagents, folds `pending/*.jsonl` → `catalog.jsonl`, runs dedup (template hash + pHash on thumbnails), regenerates `INDEX.md` and the contact sheet every ~30 min, and posts a one-line progress summary Gene can glance at.

## Curation UX

**The contact sheet** — one self-contained HTML per session (`factory/review/<date>.html`, served by a 40-line review server that also accepts verdict POSTs). Grid of cards:

- Visual asset card: 3-frame filmstrip + hover-plays motion.gif, the 3 param-sweep thumbs beneath (so param diversity is visible at a glance), id/category/tags/slot, fps number, judge score + one-line critique.
- Music asset card: play button (local webm bounce), a small band-energy bar chart from meter.json, genre/role/cps-range/key, the pattern string excerpt.
- Three buttons: **★ gold / ✓ keep / ✗ kill**, plus a note field ("fix: hips too stiff" re-queues the asset with the note as an authoring directive).

Verdicts append to `catalog/review.jsonl` and fold into asset rank at the next orchestrator pass. **Rank tiers drive stage retrieval**: gold > keep > unreviewed > quarantine (passed gates but judge <3). Unreviewed assets are usable on stage but rank below anything Gene has touched — so the library is useful from day one and gets sharper exactly where Gene spends attention. Killing an asset moves it to graveyard (never deletes — its hash prevents a fabricator from regenerating the same dud).

## Quality gates (summary — nothing enters the catalog without all of these)

compile · zero runtime errors over 10s · fps ≥30 in-cell · not-static/not-strobing motion · no blackout/whiteout · audible-within-2s + no clipping (music) · declared deps complete · param-responsiveness (params provably do something) · all-3-sweep-vectors pass · tempo-portability (visuals) · judge ≥2/5 · not a near-duplicate (template hash + thumbnail pHash vs. catalog and graveyard)

## Growth plan — first three sessions

- **Session 1 — the figurative kit (~80 assets).** Stage requests are figurative ("penguin DJ under a disco ball"). Build: 30 characters on a **shared rig** (generalize disco_dancers' pose-param interface {dy, tilt, hipX, arms, legs, crouch…} + per-figure palette dicts — penguin, DJ, dancers, animals from ideas.md), 15 props (disco ball, DJ booth, laser rig, speakers, instruments), 15 worlds (extend the 8 cached-buffer worlds), 10 floors, 10 fx overlays. After this session, the penguin-DJ request is retrieval + 4 curls.
- **Session 2 — music whitespace (~100 assets).** Parametrize the 5-stem skeleton (`${root}/${mode}/${gain}` — kills the everything-in-A-minor monoculture) across 12 genres × ~8 role stems, deliberately spending the unused engine surface: `.duck` sidechain for house/disco/trance, FM for electro/gamelan/bells, wavetables, the 6 untouched drum banks, `.striate/.slice` for footwork/concrète. Ship the machine-readable sample-pack manifest + preload preamble as the first "asset."
- **Session 3 — art scenes, transitions, harvest (~70 assets).** 25 generative-art scenes from the wanted-but-missing list (reaction-diffusion on coarse offscreen grids, truchet, circle packing, differential growth, feedback buffers, kinetic typography), 10 post/camera layers (shake, zoom-feedback, chromatic wash), 10 risers/transitions, plus a harvest pass mining `shows/full_show.show.json` and the 511-entry journal for proven code → templates.

Weeks 2+: alternate whitespace sessions (genre by genre) with "fix" re-queues from Gene's review notes.

## Catalog maintenance at 1000+

- **INDEX.md is generated, never hand-edited** — the stale `livecode-compose.md` catalog (lists 4 scene files that don't exist) proves hand-maintained indexes rot. One line per asset: `id | kind | slot | category | subject | tags | energy 1-5 | cps-range | key | deps | judge | rank | 8-word description`. Split into `INDEX_visual.md` / `INDEX_music.md` past ~500 lines. Stage retrieval = grep INDEX → read one asset.json → compile → curl: **<10s from request to pixels.**
- **Dedup at ingest**: normalized-template hash + param-schema similarity + thumbnail pHash (PIL, cheap); near-dups auto-quarantine for the next contact sheet with a "vs. existing" side-by-side.
- **Tag discipline**: closed category vocabulary (the journal's de facto taxonomy: faces-portraits, creatures-single-hero, cities-structures, …) validated at catalog time; free tags lowercased and schema-checked. The stage agent's diversity mandate (no category repeat in last 10–12) becomes a catalog query instead of parsing 456KB of journal.
- **Retirement by usage**: stage sessions log fired asset ids to the journal (one field added to the entry format); assets unpicked for N sessions and still unreviewed drop to quarantine; golds never retire. Quarterly graveyard sweep is a Gene decision, surfaced on a contact sheet.
- **Reproducibility doctrine preserved**: the catalog compiles to literal code strings inlined into shows/steps at fire time; `.show.json` files never reference the library; old shows keep playing forever as the library evolves.

## What has to be built (all small)

`factory/stack.py` (cell = controller + headless Playwright + meter injection, ~150 lines forked from autopilot_host.py) · `factory/compile.py` (string.Template + param validation, ~60) · `factory/checks.py` (the gates, ~250) · `factory/sheet.py` + review server (~150) · `factory/run.py` orchestrator harness (~120) · `assets/CONTRACT.md` · queue/catalog file conventions. Zero changes to livecode_server.py or livecode.html are required to start; the one worthwhile server addition later is `/show/append` for stage-time section buffering, which is out of this factory's scope.

### EX
**factory/checks.py — the visual verify pass** (sketch of the gates that run against a cell's Playwright page):
```python
async def verify_visual(page, cell, layer_name, subject):
    frames = []
    for t in (1, 4, 8):                       # 10s soak
        await asyncio.sleep(t - (frames and 4 or 0))
        frames.append(await page.evaluate(
            "document.querySelector('canvas').toDataURL('image/jpeg',0.7)"))
    errs = requests.get(f"http://localhost:{cell.port}/errors").json()["errors"]
    if any(layer_name in e["message"] for e in errs): return fail("runtime-error", errs)
    fps = await page.evaluate("window.state.__fps")   # meter snippet, injected at stack boot
    if fps < 30: return fail("fps", fps)              # margin over the >=20 stage floor
    a, b, c = [to_gray(decode(f)) for f in frames]
    motion = (absdiff(a, b).mean() + absdiff(b, c).mean()) / 2 / 255
    if motion < 0.004: return fail("static", motion)  # nothing moves
    if motion > 0.30:  return fail("strobe", motion)  # flashing/whiteout accumulation
    lum = c.mean() / 255
    if lum > 0.92 or lum < 0.02: return fail("whiteout/blackout", lum)
    judge = await llm_judge(frames, subject)          # "recognizably a {subject}? 1-5 + critique"
    if judge.score < 2: return fail("judge", judge)
    return ok(fps=fps, motion=motion, judge=judge)

async def gate_param_response(page, cell, asset, default_frame):
    v = sample_vector(asset.params, seed=1)
    deploy(cell, compile_asset(asset, v))
    await asyncio.sleep(2)
    alt = await grab_frame(page)
    if absdiff(default_frame, alt).mean() / 255 < 0.01:
        return fail("params-ignored", v)              # knobs must provably do something
```
Music verify mirrors this with `window.state.__meter` (AnalyserNode RMS/peak/bands, injected once via /strudel/send): RMS above floor within 2000ms enforces the never-silent mandate per-asset, so the stage agent can skip its 2s /status recheck for catalog assets.

RISKS
- Headless-Chromium audio is the shakiest link: WebAudio clocks and rAF can throttle in headless/backgrounded contexts, and MediaRecorder bounces may come out glitched or silent — if so, music curation degrades to AnalyserNode numbers with no audible preview, which is a much weaker signal for Gene's taste-driven review. Mitigate with --disable-backgrounding/--autoplay-policy flags and a day-one spike test of one cell's audio path before building the rest.
- The fps gate measures a lie: factory cells run 1280x720 headless while the stage runs retina fullscreen (measured 15-20fps in heavy scenes), and 4 concurrent Chromiums add contention noise. The 30fps in-cell margin plus the quiet-slot measurement helps, but some passed assets will still drop frames on stage until pixelDensity(1) lands and a stage-resolution spot-check pass is added.
- LLM self-judging composition is unreliable at the exact thing that matters — 'looks good' vs 'technically renders a penguin' — so the auto-gates guarantee safety (no errors, no silence, no whiteout) but not quality. If Gene's 'here and there' review lags behind ~100 assets/session, the unreviewed tier dominates retrieval and stage output quality rests on the weakest gate. The rank system contains this but can't fix it; review throughput is the real ceiling on library quality.
- Parametric templates can re-institutionalize sameness with extra steps: one penguin rig with 4 knobs is still one penguin, and the journal shows the agent already collapses to a single macro-template under pressure. Diversity has to be enforced upstream in the work-order queue (mandatory style constraints, category quotas, whitespace-first sessions) — if queue generation gets lazy, the factory mass-produces the same look it was built to escape.
- Index/contract drift is a proven failure mode in this repo (livecode-compose.md already lists four scene files that don't exist). The design survives only if INDEX.md and asset.json gate blocks are exclusively machine-written; the first hand-edit or fabricator that skips the orchestrator fold reintroduces rot, and a stale index under stage pressure is worse than no index.
- Port hygiene and shared-file contention are small but real: a fabricator that accidentally targets :8766 pollutes a live session's auto-recorded timeline, and 4 cells writing catalog/queue files need the per-cell staging discipline actually followed by subagents — both are one sloppy prompt away from corruption, so stack.py must hard-refuse port 8766 and fabricators must never write catalog.jsonl directly.
