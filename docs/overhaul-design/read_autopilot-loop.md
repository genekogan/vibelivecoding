FACTS
- Loop architecture (autopilot.md:16-38): three long-lived pieces — livecode.py server (WS 8765 / REST 8766), autopilot_host.py (headed Playwright Chromium that auto-clicks Start and samples snapshots), and the Claude session itself running /loop with ScheduleWakeup ~every 60s. The agent IS the autopilot; no background script.
- Per-round protocol (autopilot.md:79-107, canonical /loop prompt): each wakeup = (1) re-read FULL instructions.md, (2) read ~12-entry journal tail, (3) optionally scan ideas.md, (4) curl /status, (5) curl /state (full code dump of all tracks+layers), (6) Read snapshots/latest.png image, (7) decide evolve-vs-transition, (8) write fresh p5+Strudel code and curl it in, (9) wait 6-8s, re-read snapshot + /status to verify, (10) append journal entry, (11) ScheduleWakeup 60s. Every step is serial within the turn.
- instructions.md is 673 lines (~10k+ words) and is mandated re-read EVERY round (instructions.md:1-4, autopilot.md:84). It contains ~15 accreted durable user directives (no-silence rules, no-monotonous-drums rules, melody-forward rules, section-clock JS snippet, whiteout rules, perf/caching rules, instrument-rotation mandates, genre percentages, video-interleave protocol) — all of which the agent must hold in context and satisfy simultaneously while writing code from scratch.
- Snapshot mechanics (autopilot_host.py:33-58, 206-255): host samples every 6s (default --interval 6.0), writes full-window page.screenshot to autopilot/snapshots/latest.png (atomic tmp+rename), rotates prev1-prev3.png, downscales via PIL to max 1280px wide so the agent's Read never exceeds LLM image limits. A second capture, canvas.png, grabs the p5 canvas via toDataURL so the agent can verify a set being built 'behind the curtain' while a fullscreen video overlays it. Default window 1280x720; --kiosk mode attaches over CDP to real Chrome in --app mode on port 9222.
- The loop already invented a precompute pipeline under load (journal tail + instructions.md:27-95, 'VIDEO INTERLEAVE'): livecode sets are limited to ~60s on screen, then dropbox/backup videos play fullscreen while the agent authors the NEXT set 'behind the curtain' — staging build_<scene>.py + resume_<scene>.sh scripts to disk, validating them, and hard-cutting at playlistDone. Instructions explicitly say 'Use parallel subagents to author scene scripts to /tmp/scene_queue/sceneN.py' and to RECYCLE old scenes ('scene7.py…scene97.py') rather than idle. /tmp/scene_queue/ is currently EMPTY (ephemeral /tmp — the whole scene library evaporated on reboot).

- Section-clock convention (instructions.md:170-201): every scene computes section = floor((millis()/1000 - window.state.t0)/secLen) % 8 from window.state.cps + window.state.t0, with an intensity array [0.2,0.4,0.7,0.9,0.3,0.6,1.0,0.4] driving element count, motion speed, ADD alpha, beat pulse, color accent; cps must be pushed to p5 state on every change and t0 nulled on transition. Any template library must speak this clock protocol to stay music-synced.

OPPORTUNITIES
- The overhaul's core idea already has a proven in-repo precedent: the 'behind the curtain' pipeline (build_X.py + resume_X.sh staged and validated during video playback, subagent-authored, two-deep queue). Generalize it: make the scene library durable (in-repo, not /tmp — /tmp/scene_queue is empty today because it evaporated), hundreds-deep instead of two-deep, and built in practice sessions instead of during video gaps.
- Kill the biggest per-round context tax: instructions.md (673 lines of accreted directives) is re-read wholesale every round. Most of it (no-silence, no-whiteout, perf caching, drum-variety, section-clock) can be baked INTO the pre-generated assets at authoring time — a validated asset that already satisfies the rules needs none of that prose at fire time. Live-round context could shrink to: user directive + asset index + 1 snapshot.
- ideas.md is a ready-made asset-library index: ~350 one-line scene concepts across ~30 categories, each with a suggested genre, and zero code. Practice sessions can walk this list and materialize each bullet into a parametric scene (build script + resume script + preview thumbnail + metadata tags), turning the brainstorm pool into a retrieval catalog.
- Templates are already implicit and extractable: 511 journal entries reveal ONE visual macro-template (cached __bg gradient + parallax silhouette bands + hero subject + ADD fx + motes) and ONE music macro-template (kit + bass + supersaw pad + lead + counter, 5 tracks). Formalizing these as parametric skeletons (palette, subject, kit, key, cps, section-arc as parameters) makes 'samey' explicit and lets diversity be enforced at the parameter level rather than hoped for in freeform generation.
- The atomic name-overwrite primitive (same layer/track names, one-frame replace) means pre-generated scenes can hard-swap gaplessly with zero transition engineering — a retrieval hit can be live in ~10ms of curls. The 60s wake cadence then bounds only DECISION latency, not authoring latency.
- Runtime debugging cycles (too-dark render, undefined-index crash, silent Strudel parse failures requiring 2s /status rechecks) all move to practice time: each library asset can be pre-verified against a headless livecode instance (snapshot-checked for fps/whiteout/blackness, /status-checked for audible tracks) exactly as the video-interleave workflow already did with canvas.png.
- Subagent parallelism is already sanctioned by the user's own durable directive ('author/refill new scenes via subagents so the queue stays fresh', 'Use parallel subagents to author scene scripts') — the overhaul can promote this from an emergency measure during video gaps to the primary practice-session build mechanism.
- The section-clock protocol (window.state.cps/t0, 8-section intensity arrays, arrange() on matching cycle counts) is a stable contract that pre-built visual and music assets can be authored against independently and still sync when paired — enabling a combinatorial library (any visual skeleton x any music skeleton at matching cps) rather than monolithic scenes.
- The journal's category tags (faces-portraits, creatures-single-hero, generative-patterns-radial, cities-structures, characters-with-story, machines-vehicles...) plus genre tags are a de facto metadata schema for the asset index; recency-dedupe logic (avoid last ~10-12 categories) already exists and can query an index instead of parsing 456KB of prose.
- Snapshot infra needs no change for the overhaul: 6s cadence, 1280px cap, atomic publish, plus canvas.png for verifying hidden builds — practice sessions can reuse autopilot_host.py as-is as the validation harness (it already recovers from page reloads and auto-clicks Start).
- Stage-performance mode ('draw a penguin DJ under a disco ball') maps to retrieval + parameter-fill: the 2026-07-02 session shows the user typing exactly such requests and the agent hand-writing penguin/dancers/lasers layers from scratch each time; a library of posable characters (penguin, dancer, DJ booth, mirror ball, laser rig) as composable layers would answer in seconds.

CONSTRAINTS
- NEVER GO SILENT is a hard user mandate: /strudel/hush is banned during performance, >=2 tracks always playing, at least 3 of 5 tracks audible in section 0 of every new mix, no note('~') or slow-attack silent intros. Pre-generated music assets must be authored+verified to be audible-from-frame-1.
- Never replace more than 2 Strudel tracks in one round; stagger genre swaps across 2 rounds; after every track send re-check /status (~2s later) because JS parse errors drop tracks SILENTLY. Any fast-fire mechanism must keep this verify step or pre-verify assets so it can be safely skipped.
- No hard cuts: /p5/clear banned; transitions are atomic name-overwrite on shared layer/track names ('__bg', 'drums', 'bass'...). Pre-built scenes must be authored against the shared name vocabulary (or include orphan-sweep lists) to swap seamlessly.
- Whiteout rules are load-bearing (learned failures): ADD-blend alpha <=35 for shapes >1/4 canvas, beams terminate on-screen (<=~height*0.4), halos <=3x subject diameter, always a fully-opaque __bg painted first (a half-painted __bg caused a real accumulating white fan in the 2026-07-02 session). Library assets must be linted/screened for these.
- Perf: target >=20fps; static content MUST use the cached-createGraphics pattern keyed on width/height (cache keys must be unique per scene version — journal shows 'hwBg2' rename needed to bust a stale cache); particle budgets capped; layer code runs inside draw() with push/pop wrap, is NOT a function (no return statements), no createCanvas/setup calls.
- p5 layers must be resolution-agnostic: canvas is createCanvas(windowWidth, windowHeight), window freely resizable live, snapshots downscaled to 1280px — pre-generated visual code cannot bake in absolute pixel sizes, and cached buffers must re-key on width/height changes.
- Strudel environment quirks: gm_* soundfonts unavailable; setcps() absent (use .cps() or /strudel/cps); .swingBy() NOT in this bundle (threw a real error 2026-07-02 — use subdivided mini-notation); sample packs (tidal-drum-machines, piano, vcsl) must be re-sent after every server restart; every track must end with .play(); unverified sample names can silently produce no audio (keep a safety-net track untouched when trying one).
- Section-sync contract: visuals and music share window.state.cps + window.state.t0; secLen must match the music's arrange() section length; cps pushed to /p5/state on every change; t0 nulled on transition. Pre-paired assets must agree on cps and section counts (4 or 8) or the visual arc desyncs from the audio arc.
- Steering must stay in-session: the loop runs as the user-facing Claude session via /loop + ScheduleWakeup (min ~60s wake floor); no sub-agent ownership of the loop, no /schedule cloud cron, no nohup'd loop — user messages in chat ARE the steering channel and must keep landing in the performing agent's context. Subagents may AUTHOR assets but not run the show.
- Diversity mandates are durable user directives: never repeat a category in the last ~10-12 journal entries; if previous 2 scenes share a genre family the next must swap; post-video set must differ from pre-video set; every 3-4 scenes insert an experimental one; banned imagery (breathing orbs, subject-less particle fields, concentric circles, plasma blobs). Retrieval logic must enforce these, not just the LLM's memory.
- User taste boundaries encoded in instructions.md: default music = synthy/warm/disco (M83/outrun/italo), melody-forward with moving phrases and explicit song-form arrange() sections, no monotonous drums (no continuous noise wash, no hh*16 default, no sd*8 baselines, kick varies across sections), >=3 instrument-palette categories stacked per mix. Pre-generated music must be authored to these specs, not generic loops.
- State persistence gotchas: window.state survives layer updates and is shared across scenes — pre-built scenes that use common keys (t0, cps, myBg) must handle stale values from the previous scene; /tmp is ephemeral (the old scene_queue vanished), so the asset library must live in the repo or another durable path.
- Two divergent loop specs exist (autopilot.md canonical prompt vs run.sh's printed prompt: 60s vs 60-120s cadence, 12 vs 8 journal-tail entries, 6-8s vs 20s verify wait) — the overhaul should pick one source of truth or a rewrite risks resurrecting the stale variant.
- Journal append is part of the loop contract (it IS the dedupe log, 456KB and growing); any speed overhaul that drops or restructures journaling must replace its recency-dedupe function with something the next round can query cheaply.
