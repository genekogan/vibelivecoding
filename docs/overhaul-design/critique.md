GAPS
- Beat-PHASE ground truth: every proposal builds visual clocks from millis()+t0 set by the binder/server, but nothing phase-locks to Strudel's actual scheduler cycle position — after every transition or stack re-eval, visuals will be tempo-correct but up to a full beat out of phase, and the pulse-on-the-kick effect everyone promises will read as slightly drunk. Nobody proposes reading the Strudel scheduler's cycle/phase from the page (or deriving phase from the audio analyser as the beat authority) — the analyser bridge is only ever framed as amplitude-reactive, not as the phase clock.
- No cue/audition channel: every fire goes straight to the audience. A DJ previews in headphones; nothing here lets Gene (or the Conductor) see/hear an incoming scene privately before the swap — no picture-in-picture preview of the queued bundle, no audition orbit routed to a second output, no thumbnail shown in chat before firing. The shadow server verifies 'technically safe', never 'is this the vibe' — the one judgment that matters on stage.
- No non-LLM control surface for T0: continuous parameters (energy, hue, cps, ball spin) route through typed-chat -> 60s wake -> LLM -> curl. All five proposals call this tier '<2s' but the decision loop is still a minute. A $30 MIDI controller or browser hotkeys bound directly to /p5/state and /strudel/cps (zero model in the loop) gives millisecond knob-turning on exactly the params the P-block standardizes — the highest-felt-bandwidth channel in a live performance, and nobody mentions it.
- Agent-runtime failure modes are unwatchdogged: the Conductor session itself is the biggest single point of failure — mid-show context growth triggering auto-compaction (a multi-minute stall), ScheduleWakeup jitter or a missed wake, API rate limits/outage while 2-4 heavy fabricators run concurrently, and the token/dollar cost of parallel fabrication during a 45-min show. The watchdog covers the server and browser; nothing covers the model.
- Set-level dramaturgy: arcs, sections, and intensity arrays all stop at scene granularity. Nothing plans or tracks the 45-minute macro-arc — how long the show has been at peak energy, when to breathe, when the finale is. Variety quotas are distributional (what fraction of scenes), not temporal (when); a show can satisfy every quota and still be aesthetically flat-lined at energy 4 for half an hour.
- No integration/sequencing plan or dress rehearsal: the five lenses define five schemas with no unification owner and no MVP ordering (variety's mutation layer explicitly depends on parametrization landing first; orchestration depends on library breadth; nobody says what ships for the NEXT gig). And no proposal includes a full-stack dress-rehearsal protocol — replaying a realistic show on the actual stage laptop/projector/audio chain before the first live outing, which is where the fps-gate-measures-a-lie and cold-cache failures will actually surface.

CONFLICTS
- Layer naming: orchestration/factory use numeric-prefix layer names (50_penguin, 80_ball) while the p5 lens uses fixed slot names (subA, fxA). Verified: /p5/state interpolates the key into `window.state.{key}` (livecode_server.py:489), so digit-leading names are JS syntax errors as state keys — the P-block parameter channel is impossible under the prefix scheme. Fixed slot names win; z-order comes from canonical install order (insertion order keeps position on replace), not name prefixes.
- Visual parametrization mechanism: factory compiles params via string.Template at deploy time (retune = recompile + redeploy) vs p5-lens runtime P-block read from window.state.P (retune = one 10ms state poke, no recompile). For visuals the P-block wins outright on stage latency and is what makes the MIDI/hotkey gap above even possible; string.Template wins for Strudel only because no runtime param channel exists there. The factory's gates should validate P-block assets, not compile-time templates.
- Orbit table and .duck semantics: strudel lens says drums->orbit 1, orchestration's bundle puts drums on 2, the existing corpus (verified) uses orbits 2-8 with drums on the default orbit. Worse, the three proposals using the sidechain wire it three ways — strudel lens puts .duckorbit(1) on the bass (bass ducks drums, backwards), factory puts .duckorbit(3) on the bass itself (self-duck, a no-op bug), variety ducks orbit 2 from the bass. docs/strudel-reference.md:249 is ambiguous about trigger-vs-victim. Resolution: one lint-enforced orbit table codified from the existing corpus, and a bundle smoke test of .duck direction BEFORE any stem authors against it.
- The ≤2-track-swap mandate vs kit firing: the durable autopilot rule (never replace >2 tracks/round, stagger genre swaps) directly contradicts strudel-lens kit fires (6 tracks at once) and orchestration's 'pre-verified bundles may hard-swap the whole stack.' Verified bundles should win — the rule exists because of unverified code — but ONLY after the browser-side last-good revert patch lands, because whole-stack re-eval means one bad merged string silences everything; until then the 2-track rule stands.
- Who decides the scene: variety's pick_scene.py constraint card claims the decision seat that orchestration gives to Conductor triage, and orchestration's heartbeat menu (a static rotating list of palette shifts and energy bumps) is itself a convergence engine that violates variety's embargo logic. Resolution: Conductor owns triage and user directives always preempt; the card fills only unspecified axes; the heartbeat draws its mutation from the picker, not a fixed menu.
- Mid-show shadow verification: orchestration runs a second Chromium verifying bundles during the performance; factory's design says cells never coexist with the live show and its own risk notes admit the fps gate is contention-noisy with concurrent browsers. Factory wins: verification is a practice-time activity; during shows, at most one verify deferred to video-interleave gaps, and stopgaps come only from the already-verified library.
- ThreadingHTTPServer: orchestration mandates it plus locks; nothing else needs it — a scene fire is ~13 serialized 10-30ms calls (~150ms, fine), factory correctly uses separate server instances per cell, and the WS relay exists for parallel traffic. The digest's own warning stands: a sloppy locking job corrupting _steps/_tracks is a worse failure than today's queuing. Defer threading until measured queuing actually hurts; separate instances win for v1.
- Log proliferation: orchestration's journal.jsonl, variety's ledger.jsonl + taste.jsonl, factory's review.jsonl + catalog.jsonl replace one journal with five files, several of which the loop must append to under load (and contract drift is this repo's proven failure mode). One append-only performance ledger should serve journaling, fingerprints, and fired-asset ids; taste/review stay practice-time artifacts. Similarly assets/ vs library/ vs catalog/ and index.jsonl vs INDEX.md vs catalog.jsonl need one owner — one directory tree, one generated index, all lenses consume it.

LEVERAGE RANKING
- 1. Durable in-repo pre-verified asset library + machine-generated grep index + atomic name-overwrite firing (all five lenses' shared core): it is the only move that converts 2-5 min of on-stage authoring into <15s of retrieval, and every other proposal is either an input to it (factory), a consumer of it (orchestration), or a policy over it (variety).
- 2. The ~30-line AnalyserNode bridge + server-pushed cps/t0 as the single clock authority (ideally phase-locked to the Strudel scheduler, per the gap above): the biggest felt-quality-per-line change in the whole overhaul — floor tiles flashing on the actual kick reads as a different product to an audience, and it makes the entire visual library tempo-portable in one stroke.
- 3. Conductor/Fabricator split with immediate nearest-neighbor stopgap + heartbeat rule: requests visibly acknowledged in ~8s and nothing stale beyond one 60s wake, and crucially it delivers that felt experience even while the library is still thin — it converts whatever coverage exists into latency, starting now.
- 4. Practice-time mechanical validation gates (audible-within-2s, fps floor, whiteout/blackout lint, param-responsiveness, never-static 90s diff): this is what evacuates the 673-line rulebook from the live context, makes fast-fire safe (pre-verified assets skip the 2s /status rechecks), and is the precondition for trusting anything else on this list on stage.
- 5. Key/root + intensity-arc parametrization of music stems (${root}/${mode} substitution, sparse/full/peak arrange() variants): the single cheapest attack on both stated problems at once — transposition kills the everything-in-A-minor monoculture (predictability), and arrange()-compiled arcs make the music evolve on its own between wakes (staleness).

OVERRATED
- The blind-combination compatibility solver (key-window intersection, mode-family algebra, density-flex, cps-range math): its own author admits blind combination yields 'harmonically legal but aesthetically dead' mixes and that curated kits must stay the performance unit — so the solver is elaborate machinery for the fallback path. On stage, kits + a ${root} knob cover ~95%; ship the schema fields, defer the solver.
- Taste memory with satiation decay: a distillation pipeline, per-dimension weights, and a decay constant that needs multi-show tuning — all to approximate 'Gene types what he wants,' which already works and always preempts anyway. The failure mode (the system refusing warm synths Gene explicitly loves, mid-show) is worse on stage than the sameness it prevents. A ban-list lint plus virgin quota captures most of the value.
- The 14-dimension novelty ledger with embargo math (>40%-in-last-20 embargoes, ≥4-dimension transition deltas, picker-refuses-on-stale-ledger): directionally right, over-specified by an order of magnitude. Category recency + virgin quota + forced-firsts gets ~90% of the anti-sameness with a tenth of the failure surface — and 'picker refuses to run because the ledger is one scene behind' is a brand-new way to freeze on stage.
- The visual->music WS one-shot bridge (fireworks triggering crashes): a genuine 'how did it do that' demo, but it bypasses recording, /state, and reconnect-restore entirely, won't replay in shows, and most audiences cannot distinguish reverse causality from good sync. The master analyser bridge (audio->visual) delivers the felt cross-modal win; this one is a fragile encore trick, not infrastructure.
- The watchdog's fps-shed heuristic (reading fps stamped into a snapshot PNG, 2-strike layer shedding): the signal path is Rube Goldberg and the real protection is upstream — pre-verified per-asset fps budgets and pixelDensity(1). Keep the watchdog's last-good re-post (genuinely valuable, ~50ms recovery); the automated aesthetic surgery on live layers is where it will misfire.
- LLM self-judge scores as a catalog rank input: factory's own risks concede the judge is unreliable at exactly the thing it gates (looks-good vs technically-renders-a-penguin). Binary safety gates are the real product; a 1-5 judge score that shapes stage retrieval launders noise into ranking. Gene's ★/✓/✗ is the only quality signal worth ordering by — design for review throughput instead.
- Mid-show shadow-server fabrication verification: running a second Chromium + audio engine on the performance laptop to verify bundles during the set risks dragging the live canvas below 20fps to gain a property (verified novel assets mid-show) that a sufficiently broad practice library makes rare. Practice breadth is the fix; mid-show verification is the astronautics.
