# p5.js Visual System — Agent Guide

**How to use the unified p5.js visual engine expertly: run it, author/parameterize
assets, validate, grade, and extend the catalog.** Read this first for any visual
work. It is the map; the two deep-reference docs it points to are
[`assets/CONTRACT.md`](../../assets/CONTRACT.md) (the spec) and
[`assets/prompts/author-brief.md`](../../assets/prompts/author-brief.md) (the authoring checklist).

> The old standalone p5 system (`p5_server.py`, `p5.html`, ws:8775) is **retired to
> `legacy/`**. Everything below is the unified `livecode.py` engine (**engine v2**).
> The p5 *drawing language* is identical; the harness around it is what changed.

---

## 1. What it is

A browser canvas (`livecode.html`) runs a full-window p5.js sketch. You don't write
whole sketches — you deploy small **layer** snippets that the engine compiles with
`new Function(code)` and calls inside `draw()` every frame, each wrapped in
`push()/pop()`. Layers stack by insertion order. The catalog under `assets/visual/`
is a library of pre-written, pre-verified, **parametric** layer snippets ("assets");
performing = retrieve an asset, fill params, fire a curl. **You almost never generate
code on stage — you retrieve and parameterize.**

Two engine-provided globals, refreshed every frame, are the entire live surface every
asset syncs to:
- **`window.state.clk`** — the clock (t, cps, beat, bar, cyc, phase, pulse, swell, section, intensity, fps). Drives ALL rhythm. Never use `frameCount` for timing.
- **`window.state.audio`** — the audio bridge (bass, lowmid, mid, treble, rms, fft[32]). Blend on top of a clk baseline; it's all-zero in silence/validation.

Full field semantics: **CONTRACT.md §"Runtime facts"**.

## 2. Running the system

```bash
python livecode.py                       # controller: WS :8765 + HTTP/REST :8766
# open http://localhost:8766/livecode.html → click "Start Audio & Visuals"
```

The canvas clock is driven by the Strudel transport. **With no track playing, the
clock can sit frozen (`clk.t` stuck) and every visual reads static.** For headless
authoring/validation keep a near-silent metronome running so the clock advances:

```bash
curl :8766/strudel/track -d '{"name":"__clk","code":"sound(\"bd\").gain(0.001).play()"}'
curl -X POST :8766/show/recording -d '{"enabled":false}'   # factories: stop auto-record
```

For a fully headless render loop (author + snapshot without a visible browser) the
factory uses a Playwright host that auto-clicks Start and samples the canvas:
`/tmp/vf_visual_host.py --snapshots-dir <repo>/autopilot/snapshots` (see FACTORY_STATE.md).
A separate music session runs its own server on **:9766** — never touch it.

### curl quick-ref (deploy/test a layer by hand, ~10ms each)

```bash
curl :8766/p5/layer  -d '{"name":"bg","code":"background(0); fill(200,80,90); circle(width/2,height/2,200);"}'
curl :8766/p5/state  -d '{"key":"P.bg","value":{"hue":140,"scale":1.6}}'   # live retune, no recompile
curl :8766/p5/read?key=clk        # inspect the clock; key=audio for the bridge
curl :8766/errors                 # recent per-layer runtime errors (deque)
curl :8766/state                  # full code dump (all layers + setup + cps)
curl -X POST :8766/p5/clear       # remove all layers
```
Full route table: **CONTRACT.md** and the project `AGENTS.md`.

## 3. Engine reality (what the p5 harness gives you)

- p5 **1.11.11, global mode, 2D only** — no WebGL/GLSL/shaders. `circle`, `fill`,
  `beginShape`, etc. are globals.
- `pixelDensity(1)`, `colorMode(HSB, 360, 100, 100, 100)` — **already set; never call
  `colorMode` or `createCanvas`.** Full-window; can resize any frame.
- Each layer's `code` runs inside `push()/pop()` (transforms/style isolated). Layer
  z-order = insertion order; replacing a layer by name keeps its slot.
- Syntax error → the OLD layer keeps running. Runtime error → caught per-layer,
  throttled 1/s, surfaced in `GET /errors`.
- **Translating a "shader" look to 2D:** compute a field into a `createGraphics`
  pixel buffer, then `image()`-upscale it. **Size the buffer adaptively — NOT a
  fixed 128–200px.** A 200px buffer upscaled ~10× to a 1920/projector screen reads
  as blocky, pixelated garbage (this shipped in ~173 assets before it was caught,
  2026-07-17). Expensive per-cell PDEs hold 60fps at 640–720px on an M3 Max, so
  perf is not the excuse. Use `BW = Math.max(360, Math.min(720, Math.round(width/2.4)))`
  and derive `BH` from it (rebuild on the `BW+'x'+BH` size key). Point-cloud /
  accumulation buffers: cap ~520 and **scale the per-frame iterate count by buffer
  area** or they go sparse/dim. Cache LUTs/palettes. Keep feedback in `S`. No
  full-canvas `filter()` (≈12ms/frame).

## 4. Authoring or editing a visual asset

An asset is one JSON file (`assets/visual/<kind>/<id>.json`) — see the schema in
**CONTRACT.md §"File formats"** and **author-brief.md**. The essentials:

- **P-block preamble, verbatim** (D/P/S/K/A) with the single token `__SLOT__`. `D`
  defaults MUST equal the `params` defaults. Bind = `code.replace(/__SLOT__/g, slot)`.
- **kind → slot** (fixed z-order `bg→floor→setA/B→subA/B/C→crowd→fxA/B→post`):
  world/genart→`bg`, floor→`floor`, set→`setA/B`, subject→`subA/B/C`, crowd→`crowd`,
  fx→`fxA/B`, post→`post`, palette→data-only.
- **Universal seven** honored with the same meaning everywhere: `hue, energy, speed,
  density, scale, x, y`. Plus factory-mandatory `style` (≥3 genuinely-divergent looks),
  `seed` (inline hash, not p5 `random()`), `alpha` (100=opaque; lower = translucent for
  VJ compositing). Read `P.*` **every frame** (pokes must take effect live).
- **Private state only under `S`** (`window.state.<slot>`); self-init from undefined;
  cache buffers keyed on `width+'x'+height`. Tolerate `t0`/beat resets.
- **Never static, colorful, resolution-agnostic, within perf budget.** Full checklist
  + the aesthetic mandate (escape the cartoon default): **author-brief.md**.

### The hard-won gotchas (learned across 130+ assets — internalize these)

1. **Motion re-phasing = the #1 silent failure.** The motion gate compares snapshots
   **8 s apart**. At cps≈0.5 that's ~16 beats, so anything driven only by `K.beat/
   K.pulse/K.cyc` looks *identical* 8 s later → reads as frozen. And a **single-frequency
   `K.t` animation** whose period lands near 8 s (e.g. `sin(K.t*0.8)`, period ~7.85 s)
   also re-phases to ~zero apparent motion. **Fix:** drive the motion floor with a
   **real-time `K.t`** term at **incommensurate frequencies** — e.g.
   `0.9*sin(K.t*0.61) + 0.5*sin(K.t*1.43+1.7) + 0.32*sin(K.t*2.29)` — so the pose never
   repeats. (This exact bug froze a swaying tree and a starfield; both fixed this way.)
2. **Dead black space fails / reads as nothing.** A mostly-black frame trips the
   luminance floor (0.02) or just looks empty on stage. Point-cloud/attractor/particle
   pieces must **accumulate enough bright iterates** (40–80k/frame into a log-density
   buffer) and fill a real fraction of the frame. Target frame-mean luminance ~0.15–0.5.
3. **Param order matters — the validator pokes the first two numeric params to max.**
   Put params that *obviously* change the render first (`energy`, `scale`, `density`);
   never `hue` first (360 wraps to red ≈ default).
4. **Small subjects read static.** A hero occupying ~3% of frame fails the motion gate
   no matter how it flails — heroes are 0.40–0.55×min(w,h); whole-silhouette displacement.
5. **Perf:** coarse pixel buffers, ≤~150 heavy ADD shapes, `shadowBlur` on few shapes
   only (it tanks fps fast), no full-canvas `filter()`, restore `blendMode(BLEND)`+
   `shadowBlur=0` at the end.
6. **Colorful by default.** Grey/near-mono defaults read as unfinished; commit to a
   real palette (iq cosine palettes are a workhorse) — grayscale only as a named style.

## 5. Validate → index (the acceptance loop)

```bash
python assets/tools/validate.py assets/visual/inbox/<id>.json   # deploys live, gates it; PASS → moves to genart/ and stamps `verified`
python assets/tools/build_index.py visual                       # rebuild assets/visual/index.jsonl (NEVER hand-edit)
```

Gates (exact numbers in **author-brief.md**): schema · clean deploy (`/errors` empty)
· fps ≥ 25 · **motion** 320px snapshots 8 s apart differ (>0.004) but don't strobe
(<0.35) · **luminance** mean ∈ [0.02, 0.92] · **params** first-two-numeric poke changes
output. Unverified assets sit in `inbox/` and never reach the index.

### Batch authoring & review tooling (`scratchpad/gf/`)

- `gf_snap.py --outdir DIR ASSET…` (or `--glob 'assets/visual/inbox/*.json'`) — deploys
  each to the canvas, captures t & t+8s frames + motion/lum/fps → `DIR/metrics.jsonl` +
  color PNGs. Flags `STATIC` when motion<0.004.
- `gf_sheet.py --dir DIR --out sheet.png --cols N` — labeled contact sheet for one-look
  vision review.
- `author_workflow.js` — the **wave** driver. `Workflow scriptPath=scratchpad/gf/
  author_workflow.js args=<[{id,name,family,recipe,kernel,style}…]>` fans out ~10–12
  subagents that each write ONE `inbox/*.json` (never touching the server); the
  orchestrator then snaps → contact-sheet → vision-critique → validates keepers →
  requeues duds with specific critique. See `scratchpad/gf/wave*.json` for the arg shape.
  **Cadence:** ≤~12 agents, one wave at a time (quota is the binding constraint).

**Canvas is single-threaded and serial: `gf_snap`/`validate`/the grader all drive the
one canvas — run them one at a time, never concurrently.** Authoring (pure text) is
what you parallelize.

## 6. Grading & taste (the browser grader)

`grade.html` (served at **http://localhost:8766/grade.html**) live-renders every
`genart` asset from `assets/visual/genart_manifest.json` (regenerate it after adding
assets — see below) with faithful clock/HSB harness, and lets a human grade each
**bad / ok / good** (keys `1/2/3` or `b/o/g`; `←/→` step, `N` next ungraded, `S` cycle
style, `E` export). It exports `visual-grades.jsonl` (`{id, grade}` per line).

- **ok** = keep in the vocabulary.
- **good** = outstanding; use as positive signal for Gene's taste on future authoring.
- **bad** = delete the asset + rebuild index; use as negative signal.

Regenerate the grader manifest whenever the catalog changes:
```bash
python3 - <<'PY'
import json,glob
json.dump([{ "id":d["id"],"name":d.get("name",d["id"]),"desc":d.get("desc",""),
  "tags":d.get("tags",[])[:8],"code":d["code"],
  "styles":(d.get("params",{}).get("style",{}) or {}).get("options",[]) }
  for d in (json.load(open(p)) for p in sorted(glob.glob('assets/visual/genart/*.json')))],
  open('assets/visual/genart_manifest.json','w'))
PY
```

**Processing a grade file** (what to do with `visual-grades.jsonl`): for each `bad`,
`git rm assets/visual/genart/<id>.json`; then `build_index.py visual` + regenerate the
manifest. Record the good/bad ids and any inferred aesthetic patterns into a durable
taste note (`research/generative/TASTE.md` and/or a memory) so future authoring biases
toward the "good" look and away from the "bad" one.

## 8. p5 drawing language quick-ref (2D global mode)

The engine gives you standard p5 globals. Colors are **HSB 360/100/100/100** (already
set). Common moves:

- Shapes: `background(h,s,b)`, `fill()/noFill()`, `stroke()/noStroke()`, `strokeWeight()`,
  `rect/circle/ellipse/line/triangle/arc/point/quad`, `beginShape()…vertex()…endShape(CLOSE)`,
  `bezierVertex/curveVertex`.
- Transforms (inside your push/pop): `translate/rotate/scale/push()/pop()`.
- Off-screen: `const g = createGraphics(w,h); g.pixelDensity(1); g.colorMode(HSB,…);`
  draw into `g`, then `image(g, 0,0,width,height)`. Per-pixel via `g.loadPixels();
  g.pixels[i..i+3]=…; g.updatePixels();`.
- Blend/raw canvas: `blendMode(ADD|MULTIPLY|SCREEN|BLEND)`, `drawingContext` (Canvas2D:
  `createLinearGradient`, `shadowBlur`, `clip`). Restore BLEND + `shadowBlur=0` after.
- Confirmed available: createGraphics ✓, drawingContext clip/shadow ✓, text()/system
  fonts ✓, loadImage('/repo/path') ✓ (but no curated images — draw with code). Full-
  canvas `filter()` ✗ (too slow). `gm_*` soundfonts / `setcps` — music side, banned.
